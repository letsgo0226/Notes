# 可逆邏輯磁帶通用模擬器：2 KB One-Liner

完整 `hsi_logic_tape_2kb.sh` 為 **1,929 bytes（包含末尾 LF）**，不含末尾 LF 為 1,928 bytes，只有一個實體行。這包含 shell 啟動、引號、轉義及 Python 整數轉換環境設定。沒有 SHA、下載器、壓縮程式載荷或外部 HSI 程式依賴。

它是 Python 實作的通用 TM 直譯器：被模擬機器只有一條以整數位置為座標的二元磁帶，以及一個每步向左或右移動一格的讀寫頭。程式碼 `P` 決定任意有限的控制狀態與轉移表，沒有 32、128 或 512 個狀態的人工上限。

這個 2 KB 界限適用於模擬器原始碼。輸入資料、完整磁帶映像和狀態紀錄可以大於 2 KB。它不把任意 PDF 自動壓成 2 KB，也不會自行理解 PDF 內容。

## 執行方式

從 GitHub 下載後執行：

```sh
curl -fsSLo hsi_logic_tape_2kb.sh https://raw.githubusercontent.com/letsgo0226/Notes/main/Notes/HSI_LogicTape_2KB_Release/hsi_logic_tape_2kb.sh
sh hsi_logic_tape_2kb.sh
```

因程式需要互動輸入，請先下載再執行，不要使用 `curl ... | sh`。

直接貼上 `.sh` 檔中的整行指令，或在檔案所在資料夾執行：

```sh
sh hsi_logic_tape_2kb.sh
```

要把任意有限檔案逐 byte 嵌入單一磁帶而不執行轉移，在 `Steps` 輸入 `-1`：

```
File:any-file.bin
P[1829]:
Steps[10000;0=unlimited;-1=encode]:-1
Save:any-file.tape
```

此時 `any-file.tape` 與來源逐 byte 相同，包括空檔、所有 256 種 byte 與尾端零值；`.json` 保存程序、初始狀態、頭位置、步數和磁帶座標。之後以該 `.json` 作為 `File:`，即可在同一連續磁帶上續跑指定程序。這實現的是：

```
forall finite D: Decode(Encode(D)) = D
```

固定小於 2 KB 的是編碼／模擬核心；磁帶映像隨輸入長度增加。

## 一致且完備的位元理論

對快照涵蓋的每個 bit 座標 `i` 設命題原子 `P_i`。磁帶值為 1 時加入公理 `P_i`，值為 0 時加入 `not P_i`，並以古典命題邏輯取演繹閉包。所有公理由同一份完整磁帶賦值滿足，所以理論一致；對只含這些原子的每個布林公式，該賦值必定判定公式或其否定，所以理論在此有限語言中否定完備。

可逆性、邏輯性質與模擬性質分別成立：快照的 byte 序列與 `[lo,hi)` 給出可逆磁帶表示；完整賦值給出一致且完備的有限命題理論；程序整數 `P` 給出有限狀態轉移表。任意程序運行後可精確恢復的是最終磁帶快照；只有保留輸入的程序（例如純編碼模式或預設 `P=1829` 的非空輸入）才會使最終 bytes 等於原始檔案。

例如，以預設程序保留一份非空 PDF 的 bytes：

```
File:Turabian Manual.pdf
P[1829]:
Steps[10000;0=unlimited]:
Save:Turabian-copy.pdf
```

`P` 和 `Steps` 直接按 Enter，分別採用 `1829` 與 `10000`。`1829` 是兩條讀取分支均保留當前 bit、向右一步後停機的機器；不是一個壓縮或文獻分析程序。

輸出包括：

- `Turabian-copy.pdf`：完整有限磁帶映像。
- `Turabian-copy.pdf.json`：程序整數、控制狀態、頭位置、累積步數及磁帶映像的邏輯範圍。

對這個預設非空檔案案例，輸出的 bytes 與來源一致，可比較：

```sh
cmp "Turabian Manual.pdf" Turabian-copy.pdf
```

本次沒有取得使用者的這份 PDF，沒有聲稱已測試其具體內容。已測試的相同流程使用 76,800-byte 二進位資料，逐 byte 一致。

`Save:` 留白，預設為來源檔名加 `.tm`。既有輸出或其 `.json` 側錄若已存在，會拒絕覆蓋。需要 POSIX shell、`printf`、Python 3.8+ 及標準函式庫。

## 完整磁帶與續跑

磁帶以 `h∈Z` 表示 bit 位置，blank 為 0。檔案的第 `x` 個 byte 放在 bit 位置 `8*x` 到 `8*x+7`，採 LSB-first；例如 byte 值 1 的 bit 位置 `8*x` 為 1。

當頭走到來源範圍外，新格子一律為 0。輸出涵蓋初始映像與所有本次讀寫過的 byte 範圍，包含負位置與右側新增區域，不裁切回原檔案長度。

JSON 中：

| 欄位 | 意義 |
|---|---|
| `p` | 精確十進位程序整數字串 |
| `q` | 控制狀態 |
| `h` | 有正負號的 bit 頭位置 |
| `t` | 累積 TM 轉移步數 |
| `lo`、`hi` | 磁帶映像涵蓋的 byte 區間 `[lo,hi)` |
| `image` | 同資料夾內對應的磁帶映像檔名 |
| `status` | `HALTED` 或 `UNRESOLVED` |

非零 origin 的映像不是原始 PDF 本身，必須搭配 JSON 的 `lo` 解釋其 byte 座標。

續跑時再次執行同一條指令，在 `File:` 輸入上次的 `.json` 檔名。程序會自動載入同資料夾的磁帶映像及原程序 `p`，不再詢問 `P`；接著輸入本次額外步數與新的輸出檔名。兩個檔案須一起保留。

`UNRESOLVED` 表示這次額外預算用盡時，機器尚未停機。`Steps=0` 表示不設步數上限，可能永不返回；不構成停機判定。恢復已停機的狀態不會增加步數。

載入的 checkpoint 被當成操作者提供的初始組態。模擬器檢查欄位、控制狀態範圍與映像長度，但不宣稱證明此前全部運行歷史，也不輸出虛假的 `verified=1`。可用下述獨立驗證器對指定來源及完整有限步數重新核對。

## 單一磁帶的儲存方式

只有一條邏輯磁帶、一個 `q` 與一個 `h`。宿主使用一個暫存檔容納所有 signed byte 座標，映射為：

```
I(x) = 2*x       if x>=0
       -2*x-1    if x<0
```

因此正負座標都落在同一份儲存，不用兩個獨立磁帶。讀入檔案的 65,536-byte 區塊只是宿主 I/O 緩衝；每一區塊不會重設控制狀態或頭位置。快照讀寫同樣保留所有邏輯座標與另一個 parity 的內容。

「單一磁帶」描述被模擬 TM 的模型，不宣稱宿主 Python 電腦的所有實體記憶體也只能是一條磁帶，亦不是固定低階 UTM 轉移表本身的發表。

## 程序整數的精確碼本

選擇 `k>=1`，非停機狀態是 `0,...,k-1`，停機狀態是 `k`，初始控制狀態為 0。每步讀取 `a∈{0,1}`，寫入 `w∈{0,1}`，移動 `D∈{-1,+1}`。

對每一條規則 `delta(q,a)=(q_next,w,D)`，令：

```
K = k+1
B = 4*K
digit(q,a) = q_next + K*[D=+1] + 2*K*w
c = sum(digit(q,a)*B**(2*q+a) for all q,a)
v = c+k-1
p = v*(v+1)//2 + c
```

`p>=0`。解碼時用整數平方根反解同一三角配對，得到 `c,k`；再抽取 `B` 進位 digit。`verify_single_tape.py` 的 `encode_table(k,table)` 可以由明文規則生成 `P`。

兩個已測試的持續運行範例：

| P | 行為 |
|---:|---|
| 1539 | 每步寫 1、向右移，保持非停機狀態 |
| 702 | 每步寫 1、向左移，保持非停機狀態 |
| 1829 | 保留當前 bit、向右一步後停機 |
| 0 | 每步寫 0、向左移，保持非停機狀態 |

以上碼本能表示每一個這種有限狀態、二符號、單磁帶轉移表：每個合法 digit 都有唯一的位置，完整表可由有限整數 `c` 保存，三角配對也可反解。因而直譯器可按 `P` 模擬任意這個碼本中的機器。

更一般的有限字母表 TM 可採固定長度二進位區塊表示符號，blank 使用全零區塊；新增有限控制狀態以追蹤區塊內的位置、讀取及改寫區塊，再移往相鄰區塊。停留操作可由輔助狀態的右／左動作模擬。這是構造性的模型模擬說明；本版沒有附上將任意高階語言編譯為 `P` 的完整編譯器，有限測試也不等於機器檢查的普遍性證明。

原始檔案長度由映像範圍保存；TM 本身只觀察磁帶符號。若演算法需要知道輸入結尾，需另外在輸入碼本加入長度或終止標記。直接放置 raw bytes 不自動提供這種自我界定格式。

歷史概念參考：A. M. Turing, *On Computable Numbers, with an Application to the Entscheidungsproblem*, §6，[原論文](https://theory.stanford.edu/~trevisan/cs172-07/turing36.pdf)。其通用機讀入其他機器的描述進行模擬；本碼本與實作是本次另行構造的，沒有使用原論文的具體轉移表。

## 獨立驗證與實測

```sh
python3 verify_single_tape.py original.bin output.tm.json
python3 verify_single_tape.py before.tm.json after.tm.json --resume
```

驗證器以另一種三角數反解、完整規則表及 signed bit 字典重播，核對 `q,h,t,lo,hi,status` 與全部磁帶 bytes。這個較大的驗證器是附帶工具，不計入也不隱藏在 1,918-byte 模擬器內；模擬器運行不需要它。

26 項實測檢查全部通過，包含：

- 完整指令大小與一個實體行、shell 解引號後的原始碼一致性。
- 76,800-byte 二進位檔的預設一步停機與逐 byte 保留。
- `Steps=-1` 對空檔、完整 0–255 byte 集合及 70,001 個零值 byte 的精確可逆嵌入與獨立重播。
- 先做可逆嵌入再續跑 19 步，與從原始檔直接運行 19 步的完整狀態及磁帶相同。
- 跨 byte、負 bit 與負 byte 座標、完整磁帶保存。
- 17+23 步續跑和一次 40 步運行的結果一致。
- 已停機狀態恢復不增加步數；空輸入及 `P=0` 的運行。
- 524,289 個連續轉移跨過 65,536-byte 載入邊界，未重設頭或機器狀態。
- 512 個非停機狀態的規則表，沒有人工狀態數上限。
- 48 個隨機規則表與獨立參考模型一致。
- 不一致的快照長度被拒絕、既有輸出不被覆蓋。

重做測試：`python3 test_simulator.py`。詳細證據：`simulation_certificate.json`。

直接測試環境為 Linux、POSIX sh、Python 3.12.14；沒有直接在使用者的 iSH 或 macOS 裝置上測試。實際運行仍受宿主時間、磁碟與記憶體資源約束。
